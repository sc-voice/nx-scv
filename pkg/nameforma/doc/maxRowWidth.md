# maxRowWidth Specification

The `maxRowWidth` property defines the maximum horizontal character width allowed for any single line of text rendered by a `MonoTable`. When the total width of a standard row exceeds this limit, the table switches from a standard horizontal layout to a hybrid layout consisting of a standard "fit" row followed by "overflow" lines for the remaining columns.

## Layout Logic

### 1. The "Fit" Phase (Standard Layout)
The table determines the largest number of columns ($N$) that can be rendered on a single line while respecting the `maxRowWidth`. 

A column is included in the standard row if:
`Width(columnSeparator) + Σ(Width(column_i) for i=0 to N) + Σ(Width(columnSeparator) for i=1 to N) <= maxRowWidth`

The standard line is constructed as:
`columnSeparator + col_0 + columnSeparator + col_1 + ... + col_N`

### 2. The "Overflow" Phase (Vertical Layout)
Any column index $i > N$ is considered an overflow column. Each overflow column is rendered on its own set of lines immediately following the standard row.

For each overflow column:
1.  **Content Construction**: The content is formed by joining the column's label (using `theme.nfLabel(column_title)`) and the cell value.
2.  **Wrapping**: This combined content is wrapped to a width of `maxRowWidth - Width(columnSeparator)`. Wrapping should attempt to break at whitespace boundaries.
3.  **Prefixing**: **Every line** generated by the wrapping process must be prefixed with the styled `columnSeparator`.

## Visual Example

**Configuration:**
- `maxRowWidth`: 25
- `columnSeparator`: ` | `
- `theme.nfLabel` style: `[Label]`

**Data:**
- Columns: `ID` (5), `Name` (10), `Email` (20), `Bio` (40)
- Row: `1, Alice, alice@example.com, A very long biography text`

**Rendered Output:**
```text
 | ID   | Name
 | 1    | Alice
 | [Email] alice@example.com
 | [Bio] A very long
 | biography text
```

## Implementation Notes
- The `columnSeparator` must be styled using `theme.nfBoundary(columnSeparator)` if it is a non-empty string.
- The wrapping logic must ensure that the prefixing of the `columnSeparator` does not cause the line to exceed `maxRowWidth`.
- All lines in the table (both standard and overflow) must strictly adhere to the `maxRowWidth` constraint.
